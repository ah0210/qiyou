# 栖游 · 整体技术架构方案

> 2026 微信小程序开发大赛参赛作品 ｜ 主题：与 AI 共生 ｜ Slogan：一人一栖迟，AI 伴你旅居中国

本文档综合四份作品的工程实践，取长补短后形成的最终架构方案：

| 借鉴来源 | 采纳的实践 |
|---|---|
| 栖游 qiyou | 双通道 AI 降级、合规溯链表、适老化统一注入 |
| 雁栖 ferrite | **`_shared` 单一权威源 + 同步脚本 + 硬校验**（端云同构根治） |
| 雁栖 estuary | 官方端侧 LLM（`wx.cloud.extend.AI`）、零依赖 Node 测试、150 项断言守门 |

## 一、总体架构

```
┌──────────────────────────────────────────────────────────┐
│                     微信小程序（原生）                      │
│  ┌────────────┐  ┌────────────┐  ┌────────────────────┐  │
│  │ 视图层 20页 │→ │ 状态层 store│→ │ 业务/算法层 utils   │  │
│  │ (wxml/wxss)│  │ 发布订阅   │  │ 纯函数引擎(权威源)   │  │
│  └────────────┘  └────────────┘  └─────────┬──────────┘  │
│                                            │              │
│  ┌─────────────────────────────────────────▼──────────┐  │
│  │ 数据访问层 cloud.js（useCloud 自动降级到 mock）       │  │
│  └─────────────┬───────────────────────────┬───────────┘  │
└────────────────┼───────────────────────────┼──────────────┘
                 │ wx.cloud.callFunction      │ 端侧 LLM
                 ▼                           ▼
┌────────────────────────────┐   ┌────────────────────────┐
│  云开发 CloudBase（云函数）  │   │ 微信官方 AI（hy3-preview）│
│  login/city/house/aiMatch  │   │ wx.cloud.extend.AI      │
│  aiChat/aiContract/companion│   │ （端侧直连，云函数不含LLM）│
│  family/policy/analytics/  │   └────────────────────────┘
│  seedData/_shared          │
└─────────────┬──────────────┘
              │ 云数据库（MongoDB 风格）
              ▼
   users / cities / housings / policies / ai_plans /
   contracts / companions / families / ai_logs / analytics_events
```

**核心设计原则（ADR）**
1. **确定性可复算**：打分/匹配/预算/合同风险全部由纯函数引擎计算，LLM 只做语言组织与增强，不产数字。
2. **端云同构有机制**：共享算法放 `cloudfunctions/_shared/`，由 `scripts/sync-shared.js` 单向分发到各云函数 + 生成端侧副本，并做 `diff` 硬校验（根治四份作品共有的「端云重复漂移」顽疾）。
3. **云端优先、本地兜底**：`useCloud` 由 `cloudEnvId` 是否为空决定；空则全量走 `mock/`（与云函数同构），保证评审零配置可跑。
4. **AI 双通道降级**：端侧官方 LLM 不可用（旧基础库/未开通/超时）→ 返回 null → 业务层走确定性规则引擎兜底，并如实标注 `model: 'rule-fallback'`。

## 二、前端架构（miniprogram/）

```
miniprogram/
├── app.js / app.json / app.wxss        # 全局逻辑/配置/设计令牌
├── config/env.js                        # 唯一环境出口（cloudEnvId 等）
├── utils/                               # 纯函数业务引擎（端侧权威源）
│   ├── store.js                         # 单一状态树 + 发布订阅 + pageBind
│   ├── cloud.js                         # 云函数调用封装（自动降级 mock）
│   ├── llm.js                           # 官方端侧 LLM 封装（hy3-preview）
│   ├── match.js                         # 六维评分 + 旅居匹配（端权威源）
│   ├── contract.js                      # 合同风险规则库（端权威源）
│   ├── budget.js                        # 预算测算
│   ├── companion.js                     # 结伴匹配
│   ├── voice.js                         # 同声传译插件封装（安全降级）
│   ├── theme.js                         # 适老大字模式
│   └── tracker.js                       # 轻量埋点
├── mock/
│   ├── data.js                          # 种子数据（与 seedData 同构）
│   └── functions.js                     # 云函数本地降级实现
├── components/                          # 3 组件：score-radar / voice-fab / role-switch
├── pages/                               # 主包 6 页（含 tabBar 5 页）
└── packages/                            # 5 分包 14 页
    ├── ai/          match / result / contract / policy
    ├── city/        detail / budget
    ├── house/       detail / compare
    ├── community/   feed / companion / post-detail
    └── senior/      toolbox / family / emergency
```

### 前端关键决策
- **状态管理**：`store.js` 单一状态树 + 发布订阅 + `pageBind(map)` mixin 把 state 映射到页面 data，无需引入 mobx/redux。
- **AI 接入**：用官方 `wx.cloud.extend.AI.createModel('cloudbase')`（`llm.js`），模型 `hy3-preview`（共享 Token 配额包内置），任何不可用返回 null。
- **设计令牌**：`app.wxss` 用 CSS 自定义属性定义颜色/字号/间距，适老模式通过根节点 `.theme--elder` 切换变量值，组件内用 `var(--xx)` 继承，根治「适老主题失效」bug。
- **语音**：`voice.js` try/catch 包裹 `requirePlugin('WechatSI')`，未授权时全部降级为文字，不影响其他功能（规避插件白屏风险）。

## 三、后端架构（cloudfunctions/）

| 云函数 | 职责 | 关键点 |
|---|---|---|
| `login` | 登录/档案 | 字段白名单 `updateProfile` 防越权 |
| `city` | 城市列表/详情 | 查库失败走 seed |
| `house` | 房源列表/详情 | 按类型/城市筛选 |
| `aiMatch` | 旅居匹配 | 三段式：硬筛→六维评分→方案；数字全代码算 |
| `aiChat` | AI 问答网关 | 场景化 prompt + 规则兜底 + 内容安全 |
| `aiContract` | 合同风险筛查 | 规则引擎 + OCR + LLM 互校 |
| `companion` | 结伴匹配 | 同城+时间重叠+兴趣 Jaccard |
| `family` | 家属绑定/SOS | 邀请码双向确认 |
| `policy` | 政策问答 | 医保/居住证/社保 |
| `analytics` | 埋点入库 | 批量写，失败不影响用户 |
| `seedData` | 种子导入 | 幂等 upsert |

**共享层 `_shared/`（单一权威源）**
```
cloudfunctions/_shared/
├── scoreCore.js     # 六维评分 + 匹配计划（权威源）
├── riskCore.js      # 合同风险规则（权威源，由端侧 risk.js 回写）
└── seedData.js      # 种子数据（权威源）
```
`scripts/sync-shared.js`（Node 跨平台版，替代 ferrite 的 bash）负责：
1. `_shared/scoreCore.js` → 分发到 `aiMatch`、`city` 云函数 + 生成 `miniprogram/utils/match.js` 评分核心
2. `miniprogram/utils/contract.js` → 回写 `_shared/riskCore.js` → 分发到 `aiContract`
3. `_shared/seedData.js` → 分发到所有需要种子的云函数 + `miniprogram/mock/data.js`
4. 最后 `diff` 硬校验端云一致，不一致即 exit 1

## 四、微信 AI 接入方案

### 4.1 端侧官方 LLM（主通道）
- 接口：`wx.cloud.extend.AI.createModel('cloudbase')` → `model.generateText({ model: 'hy3-preview', messages })`
- 要求：基础库 ≥ 3.15.1，云开发控制台 → AI → 生文模型开启
- 封装：`utils/llm.js` 提供 `chat` / `chatJSON` / `streamChat` / `available()`
- 兜底：返回 null → 业务层走确定性引擎，`model` 字段标注 `rule-fallback`

### 4.2 三段式防幻觉（AI 只做语言组织）
```
硬约束筛（预算 1.1 弹性）→ 六维加权评分（权重随身份）→ 方案生成（数值代码计算）
                                                              ↓
                                            LLM 仅把已算结果转成口语化叙述
                                            system prompt 明确"只用给定数据、不编造数字"
```

### 4.3 微信 AI 生态原子接口（ai-skills/）
```
miniprogram/ai-skills/
├── match/    mcp.json + SKILL.md + index.js   # 旅居匹配
├── budget/   mcp.json + SKILL.md + index.js   # 预算测算
└── policy/   mcp.json + SKILL.md + index.js   # 政策问答
```
每个接口 = 参数 schema（mcp.json）+ 流程约束（SKILL.md）+ 原生实现（index.js），对齐「与 AI 共生」主题。

### 4.4 内容安全（AI 相关）
- `aiChat` 输入走 `msgSecCheck`（v2），risky 则 blocked
- `companion`/`community` UGC 发布前统一检测，87014 双路径拦截

## 六、可运行性保证（零配置评审可跑）

- `config/env.js`：`cloudEnvId` 默认为空 → `useCloud = false` → 全量走 `mock/`
- `mock/functions.js`：与云函数同构的本地实现，返回 `traceId`/`model: 'mock-rule-v1'`
- `mock/data.js`：种子数据，与 `_shared/seedData.js` 由同步脚本保证一致
- 一键校验：`npm run all`（Node ≥ 16，纯 Node 脚本，Windows 原生可跑）

## 七、部署

1. 微信开发者工具导入 `qiyou/`，填 AppID + 云环境 ID（`config/env.js`）
2. `npm run all` 本地复核
3. 部署 11 个云函数（login→city→house→aiMatch→aiChat→aiContract→companion→family→policy→analytics→seedData）
4. 手动调用一次 `seedData` 导入种子
5. 后台添加「同声传译」插件授权、填写隐私保护指引、报名小程序成长计划

详见 `docs/03-部署文档.md`。
